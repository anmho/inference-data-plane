# Local MLX Benchmark: 2026-07-18

## Environment

- Hardware: Apple M5 Pro, 18 cores, 64 GB memory
- Kubernetes: Minikube `inference`, Kubernetes 1.34.0, 8 CPUs, 16 GiB
- Model: `mlx-community/SmolLM2-135M-Instruct`
- Model revision: `422de227b90002f443a21a58b1087f6ee7632731`
- API: ConnectRPC-compatible protobuf over HTTP/2
- Broker: Valkey Streams
- Load: 2 unary VUs and 1 streaming VU for 20 seconds
- Unary prompt: 37 model-reported prompt tokens, maximum 32 output tokens
- Streaming prompt: 36 model-reported prompt tokens, maximum 24 output tokens

## Commands

```bash
make bench
```

The benchmark starts from a stopped MLX process, loads the model through the Temporal lifecycle workflow, waits for the real KServe endpoint, runs unary/stream/replay smoke checks, runs k6, and stops the host-owned model process on exit.

| Measurement | Result |
| --- | ---: |
| Model cold start to KServe ready | 3.291 s |
| Smoke unary latency | 244 ms |
| Smoke stream TTFT | 61 ms |

| Completed-stream replay | 47 ms |
| k6 requests | 79 |
| Overall request rate | 3.872 req/s |
| Unary request rate | 2.549 req/s |
| Streaming request rate | 1.323 req/s |
| Generated-token rate | 110.772 tokens/s |
| Overall latency p50 / p95 | 629.567 ms / 1.332 s |
| Unary latency p50 / p95 | 625.926 ms / 1.220 s |
| Streaming completion p50 / p95 | 630.005 ms / 1.481 s |
| Error rate | 0% |

`generated-token rate` is application throughput: cumulative generated tokens returned across all successful requests divided by benchmark wall time. It is not isolated single-sequence decoder throughput. k6 buffers the response, so its streaming latency is completion latency; TTFT comes from the Rust streaming client reading the first non-empty protobuf envelope.
